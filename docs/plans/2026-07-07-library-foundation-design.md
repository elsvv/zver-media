# Фундамент библиотеки: избранное, история, полировка, правка метадаты, discovery

Этап 1 из 3 большого батча «современный музыкальный плеер»
(2 — таб «Главная» + AI-рекомендации, 3 — редизайн ZverMac; у них свои дизайн-доки).

## Scope

- **A. Полировка iOS**: подсветка текущего трека, аудит миниплеера,
  case-insensitive артисты, «Недавно добавленные» в Библиотеке.
- **B. Избранное**: треки и альбомы.
- **C. Правка метадаты на телефоне**: название/артист/год альбома через sidecar.
- **D. История прослушивания**: события воспроизведения, сырьё для рекомендаций.
- **E. Discovery в альбоме**: карусели «Ещё от артиста» / «Из того же года».

## Хранение (миграция v6)

Избранное и история живут в `catalog.sqlite` — по прецеденту плейлистов
(переживают реинсталл через облачный бэкап `catalog.sqlite.backup`; рескан эти
таблицы не трогает).

```
favorite:  entityKind TEXT ('track'|'album'), entityKey TEXT, createdAt DATETIME
           PK (entityKind, entityKey)
playEvent: id AUTOINCREMENT, trackKey TEXT, title TEXT, artist TEXT, album TEXT,
           albumKey TEXT, startedAt DATETIME, playedSeconds DOUBLE,
           trackDuration DOUBLE, endReason TEXT ('finished'|'skipped'|'stopped')
```

- `entityKey` трека — `trackKey`; альбома — путь папки (`AlbumGroup.id`,
  стабилен: `albumId` синка детерминирован, перезаливка кладёт в ту же папку).
- **Без FK на `track`**: избранное/история переживают офлоад и удаление файла.
  История денормализована (снапшот title/artist/album) — пригодна для
  статистики даже по удалённым трекам.
- «Прослушал» для агрегатов = `playedSeconds ≥ 30с || ≥ 50%` — правило
  потребителя (`PlayHistoryStore`), события пишутся все.
- Запись события: `PlayerEngine` при смене трека / остановке / окончании.

## Решения по фичам

- **Подсветка текущего трека** — общий модификатор ряда: сравнение
  `track.id == engine.queue.current?.id` → title акцентным цветом + иконка
  эквалайзера. Применить в альбоме, Песнях, плейлисте, поиске.
- **Миниплеер** — схема `safeAreaInset` на каждом `NavigationStack` остаётся;
  аудит всех скроллящихся экранов/шитов на контент под баром, фикс найденного.
- **Артисты case-insensitive** — чистая функция в ZverCore (`ArtistKey`):
  ключ = trim + `lowercased()`; отображаемое имя — вариант написания
  большинством голосов (как `displayTitle` у AlbumGroup). Использовать в
  списке артистов, фильтре по артисту, каруселях discovery.
- **Недавно добавленные** — `LibraryView`: сверху категории, ниже секция-грид
  «Недавно добавленные» (recency = max `addedAt` треков папки), 12 плиток +
  «Показать все» (полный грид). Плитка — та же, что в Альбомах.
- **Избранное UI** — сердечко в контекст-меню/swipe трека, кнопка на экране
  альбома; раздел «Избранное» в Библиотеке (альбомы-грид + треки).
- **Правка метадаты** — шит «Править альбом» из меню альбома: название, артист
  альбома (во все треки), год. Пишется в `album.zvermeta.json`
  (существующий `TrackOverride`), затем рескан → overlay в каталоге.
  Осознанный нюанс: перезаливка с Мака перезапишет sidecar (Мак главнее).
- **Discovery в альбоме** — под списком треков: карусель «Ещё от {артиста}»
  (тот же нормализованный артист, минус текущий альбом); «Из того же года»
  при ≥3 альбомах. Пустые секции скрыты.

## Верификация

Чистая логика (миграция, стороны favorite/history, ArtistKey, sidecar-мёрж) —
юнит-тесты в SPM-пакетах. UI — сборка iOS-таргета. На устройстве пользователь
не проверяет.

## PR-разбивка

Одна ветка `feat/library-foundation`, логичные коммиты: (1) полировка A,
(2) v6 + избранное + история, (3) правка метадаты + discovery.
