# Диски через папки + m3u (folder/playlist-driven discs)

Дата: 2026-07-02. Статус: согласовано, в реализации.

## Проблема

Диски (и стороны винила) реальные рипы кодируют **структурой папок** + плейлистом
в корне альбома, а не тегами. Пример: `Tricky - Maxinquaye (Reincarnated) 5 CD`:

```
<album root>/
  cover.jpg
  playlist.m3u8          # список путей: CD1/01 - ....flac, CD1/02..., CD2/01...
  CD1/  01 - Overcome.flac ... (12)
  CD2/  01 - Strugglin'.flac ... (6)
  CD3/ CD4/ CD5/
```

У этих файлов **нет тега DISCNUMBER вообще** — диск только в имени папки и в
плейлисте (TRACKNUMBER перезапускается на каждом CD). Наши ТГ-альбомы — зеркально:
теги `DISCNUMBER` есть, но папки плоские (Telegram — это сообщения).

Ранее (PR #6) отгружен tag-based `discNumber: Int?`. Теперь делаем основным
механизмом папки+плейлист, тег — запасной.

## Решение

### Приоритет источника диска (на трек)
1. **Плейлист** (`.m3u`/`.m3u8`) в корне альбома → диск/порядок из путей плейлиста.
2. Плейлиста нет, но трек в подпапке корня → метка = имя подпапки, порядок —
   натуральная сортировка подпапок.
3. Плоско (ни плейлиста, ни подпапок) → тег `DISCNUMBER` → метка «Диск N».
4. Один диск → без заголовков (обычный альбом).

### Структура сохраняется end-to-end (ZverMac не расплющивает)
- `ManifestTrack.relativePath: String?` — путь внутри корня альбома
  (`CD1/01 - ....flac`). Старые манифесты без него → эффективный путь = `fileName`
  (плоские альбомы совместимы).
- Плейлист передаётся как файл-компаньон (`ManifestAlbum.playlist: ManifestFile?`,
  как обложка: имя+sha+size). Обложка уже передаётся (`artwork`).
- Телефон воссоздаёт дерево: `Documents/<albumId>/CD1/…`, `cover.jpg`,
  `playlist.m3u8` — как в дропнутой папке. `FileServer`/`DownloadEngine` работают
  по относительному пути (создавая подпапки).

### Идентичность альбома
Корень альбома = ближайшая папка-предок трека, содержащая плейлист ИЛИ обложку;
иначе — непосредственный родитель (прежнее поведение). Так `CD1..CD5` — ОДИН
альбом, а не пять. Плоские альбомы не меняются.

Ключи sidecar и m3u — по относительному пути внутри альбома, НЕ по `lastPathComponent`
(иначе `CD1/01.flac` и `CD2/01.flac` конфликтуют).

### Модель
К `discNumber: Int?` (ordinal для сортировки) добавляем `discLabel: String?`
(метка для UI) во все слои: Track, AudioFileInfo, TrackOverride/AlbumSidecar,
ManifestTrack, TrackRecord (+ миграция каталога v4). Заголовок секции =
`discLabel ?? "Диск \(discNumber)"`. Номер трека в ряду — позиция внутри диска из
плейлиста, тег `TRACKNUMBER` как запасной. Сортировка — `(discNumber, trackNumber)`.

### M3U
Парсер сохраняет относительный путь записи и выдаёт: relativePath →
(discLabel = ведущий сегмент или nil, discOrdinal = по первому появлению,
positionWithinDisc). Порядок диска и трека — из плейлиста (надёжно даже без тегов).

### organize.py (единообразие)
Много-дисковые альбомы (различает `DISCNUMBER`-тег) раскладывает в подпапки
`CD1/CD2/…` и пишет `playlist.m3u8` (пути `CD1/<file>` в порядке диск→трек).
Одно-дисковые не трогает. Пере-синкаем 4 альбома: Mezzanine, Bitches Brew,
Kid A Mnesia, OK Computer OKNOTOK.

## Тесты
- M3U: путь → сегмент-диск + порядок внутри диска; `.m3u8` UTF-8.
- Определение корня альбома (плейлист/обложка/родитель).
- Round-trip `relativePath`/`discLabel` в манифесте; обратная совместимость.
- Воссоздание дерева при скачивании; коллизия `CD1/01` vs `CD2/01`.
- Группировка с метками; плоские альбомы не меняются.
- organize.py: раскладка по дискам + генерация плейлиста.

## Порядок работ
Транспорт (relativePath + playlist) → скан/диски (root + m3u + discLabel) →
UI (метки секций) → organize.py → сборка+тесты → мердж → деплой → импорт Tricky
+ пере-синк 4 альбомов → проверка на телефоне.
