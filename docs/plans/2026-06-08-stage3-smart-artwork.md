# Этап 3 (доработка) — умное определение обложки

**Дата:** 2026-06-08
**Статус:** дизайн утверждён владельцем

## Зачем

Текущее автоопределение обложки из папки распознаёт только 4 жёстких имени
(`cover`/`folder`/`front`/`albumart`, расширения `jpg/jpeg/png`) и не берёт ничего,
если имя другое (`artwork.jpg`, `front cover.jpg`, `AlbumArtSmall.png`, `.webp`,
`scan01.jpg`). Реальные раздачи называют обложку по-разному → альбом часто без
картинки. Делаем определение умнее: больше имён + фоллбэк на самую крупную картинку,
с сохранением ручного выбора на Маке.

## Решения (из брейншторма)

- Авто: расширенный список имён + при отсутствии совпадения — **самая большая
  картинка** (по разрешению). Передняя обложка почти всегда крупнее back/booklet/disc,
  поэтому промахов мало.
- Ручной выбор на Маке («Заменить обложку…») — **без изменений**: только файл, уже
  лежащий в папке альбома.
- Приоритеты сверху не меняются: sidecar `artworkFileName` (правка с Мака) >
  встроенная обложка в тегах > файл из папки (по новой логике).

## Где меняем

Только `Packages/ZverMetadata/Sources/ZverMetadata/LibraryScanner.swift` — общий код
сканера, его используют и импорт через Files на iPhone, и drag-drop на Маке.
Цепочка синка, Mac-редактор, sidecar, reconcile — **не трогаем** (улучшение само
приедет: `AlbumDraft.from` и каталог берут `artworkFileURL` как и раньше).

## Реализация

1. **Список имён** (точное совпадение имени без расширения, регистронезависимо,
   в порядке приоритета): `cover`, `folder`, `front`, `front cover`, `albumart`,
   `albumartsmall`, `album`, `art`, `artwork`.
2. **Расширения:** `jpg`, `jpeg`, `png`, `webp`.
3. **`artworkFileURL(inFolder:)`:** сперва известные имена по приоритету; если ни одно
   не подошло, но в папке есть картинки указанных расширений — вернуть самую крупную
   через `largestImage`.
4. **`largestImage(among:)`** (новый, private): счёт = (пиксели = ширина×высота через
   `ImageIO`/`CGImageSourceCopyPropertiesAtIndex` без полного декода; тай-брейк —
   размер файла). Кандидаты уже отсортированы по имени по возрастанию; выбираем первый
   со строго бóльшим счётом → при равенстве остаётся алфавитно первый (детерминизм).
   Нечитаемые как изображение → счёт (0,0).
5. `import ImageIO` (кросс-платформенный, iOS+macOS).

Именованное совпадение возвращается БЕЗ чтения размеров (приоритет имени над размером:
маленький `cover.jpg` побеждает большой `back.jpg`). Размеры читаются только в фоллбэке.

## TDD (Packages/ZverMetadata/Tests)

Тесты через `LibraryScanner.scan` над временными папками (копируем `notags.flac` —
без тега и без встроенной обложки — и генерируем PNG нужных размеров в тесте через
`CGImageDestination`):

- `front` побеждает `back` при обоих присутствующих (приоритет имени, не размер);
- регистр игнорируется (`COVER.JPG`);
- `webp`-обложка с известным именем распознаётся;
- нет узнаваемых имён → берётся самая большая по разрешению картинка;
- детерминизм при равном разрешении (алфавитно первая);
- в папке нет картинок → `artworkFileURL == nil`;
- регрессия: существующее поведение `cover/folder/front/albumart` сохраняется
  (старые тесты зелёные).
