# Zver Cloud — дизайн системы

**Дата:** 2026-06-06
**Статус:** утверждён (брейншторм-сессия с владельцем проекта)

## Что это

Личная система синхронизации и воспроизведения lossless/hi-res музыки:
нативное iOS-приложение (библиотека + плеер с выводом на USB ЦАП) +
Mac-компаньон (заливка альбомов, редактор метадаты, пульт) +
Яндекс.Диск как холодный ярус хранения и бэкап. Без собственного бэкенда,
но с архитектурой, готовой к его появлению.

## Контекст и ограничения

- **Устройство:** iPhone 12 mini, iOS 18.7.1, мало памяти. Подключён к
  внешнему USB ЦАПу через Lightning → USB, ЦАП → усилитель.
- **Библиотека:** большая (не влезает на телефон целиком) — FLAC, ALAC,
  hi-res 24/96–24/192, потенциально DSD. Источник: раздачи, оцифровки винила.
- **Дистрибуция:** бесплатный Apple ID + AltStore (авто-переподпись по Wi-Fi,
  AltServer на Маке). Без App Review — допустимы «личные» хаки.
  CloudKit/Push недоступны (нужен платный аккаунт) — не используем.
- **Один аккаунт/пользователь** в MVP, но модель не должна мешать
  многопользовательности в будущем.

## Ключевые выводы ресёрча (2026-06)

### Аудио (реализуемо полностью нативно)
- FLAC декодируется системно с iOS 11 (`AVAudioFile`), 24/192 без ресемплинга.
- USB ЦАП: `AVAudioSession.setPreferredSampleRate` реально переключает
  частоту ЦАПа; обязателен readback-чек (баг iOS 18.0: readback врёт —
  обходится «ставим-и-проверяем»). Громкость 100% + ноль DSP =
  функционально bit-perfect.
- Gapless: `AVAudioPlayerNode.scheduleFile` следующего трека заранее;
  при смене частоты — рестарт engine (микропауза, как у всех).
- DSD: нативно нет; SFBAudioEngine (MIT, iOS 15+) даёт DSF/DSDIFF + DoP.
- Метаданные FLAC: `AVURLAsset.commonMetadata` ПУСТОЙ для FLAC;
  работает `asset.metadata(forFormat: "org.xiph.vorbis-comment")` +
  artwork через `METADATA_BLOCK_PICTURE` (сырые байты картинки).
  Fallback: AudioToolbox `kAudioFilePropertyInfoDictionary`, FLACMetadataKit.
- Референсы: SFBAudioEngine, LyrPlay (sample-rate-matching логика),
  AudioStreaming (dimitris-c).

### Локальная сеть (pull-модель — единственно надёжная)
- HTTP-сервер на iPhone умирает при сворачивании приложения («You cannot
  set up a network server that runs in the background» — Apple DTS).
  Исключение: при активном background audio приложение не суспендится
  и сокеты живут.
- Pull: сервер на Маке, iPhone качает `URLSession.downloadTask` —
  докачка бесплатно (HTTP Range + resume data), background URLSession
  доносит даже при убитом приложении. Скорость 30–80 МБ/с.
- Multipeer Connectivity — медленный, не использовать.
- GCDWebServer/Swifter мертвы; живой embedded-сервер — FlyingFox (MIT).
- Local Network privacy (iOS 14+): `NSLocalNetworkUsageDescription` +
  `NSBonjourServices` в Info.plist; на macOS 15+ аналогичный промпт.
- Bonjour не ходит между VLAN — устройства в одном L2-сегменте.

### Пульт (без сервера — да)
- Пока играет музыка (background audio), iOS-приложение живо и держит
  сокеты → Mac управляет по WebSocket, задержки мс (подтверждено Apple DTS,
  thread 105061).
- На паузе приложение суспендится → пульт слепнет. Обход: тишина
  (нулевые сэмплы) держит сессию. Для личного приложения легально.
- MPRemoteCommandCenter обязателен: локскрин, Control Center, Apple Watch.
  Системного способа «Mac управляет iPhone» не существует.

### Яндекс.Диск (только REST API)
- REST API живой: двухэтапный upload/download по временным ссылкам
  (href живёт 30 мин — запрашивать перед стартом задачи), докачка
  `Content-Range`, app-folder scope, async-операции с поллингом.
- WebDAV троттлится до ~1.5 МБ/с — не использовать.
- OAuth: регистрация приложения без модерации, `ASWebAuthenticationSession`
  или отладочный токен (~год жизни), хранить в Keychain.
- Цена: 1 ТБ ≈ 191–399 ₽/мес (Яндекс 360). Лимит файла на платном — 50 ГБ.
- SDK мертвы — пишем свой тонкий клиент (~6 эндпоинтов).
- Риск: Яндекс закручивает гайки (paywall десктоп-клиента 06.2026) →
  storage-слой строго за протоколом, план Б — Yandex Object Storage (S3).
- Ретраи с exponential backoff на 429; 2–4 параллельных передачи максимум.

## Архитектура

```
┌─────────────────┐  Bonjour + HTTP/WS   ┌──────────────────┐
│   Zver Mac      │ ◄──────────────────► │   Zver iOS       │
│  (menu bar +    │    локальная сеть     │  (библиотека +   │
│   окно заливки) │                       │   плеер + ЦАП)   │
└────────┬────────┘                       └────────┬─────────┘
         │                REST API                 │
         └──────────► Яндекс.Диск ◄───────────────┘
                    (холодный ярус + бэкап)
```

Монорепо, Swift 6, SwiftUI. Таргеты: iOS 17+, macOS 14+.

```
zver-cloud/
  Packages/
    ZverCore/        ← модели, каталог (GRDB), file states
    ZverMetadata/    ← парсинг тегов FLAC/ALAC/…, artwork
    ZverTransport/   ← Bonjour, протокол синка и пульта (JSON-схемы)
    ZverStorage/     ← RemoteStore + YandexDiskStore
  Apps/
    ZverIOS/         ← SwiftUI приложение, плеер (AVAudioEngine)
    ZverMac/         ← menu bar + окно заливки + пульт
  docs/plans/
```

Зависимости: GRDB; опционально SFBAudioEngine (DSD/экзотика); остальное —
системные фреймворки.

## Модель данных

Каталог — SQLite (GRDB) на телефоне. **Телефон — каталог-источник правды;
файлы — по требованию** (память маленькая, библиотека большая).

```
Album    — id, title, artist, year, artworkPath, addedAt, sortKeys
Track    — id, albumId, title, trackNo, discNo, duration,
           format, sampleRate, bitDepth, fileSize,
           checksum (SHA-256), fileState
Playlist — id, title, упорядоченный [trackId]
Artwork  — файлы (full + thumb), не в базе
```

**fileState:** `local` | `remote` (только метаданные, ☁️ в UI, тап → скачать)
| `downloading` | `uploading`.

Жизненный цикл: Mac отправил → `local` → фоновый бэкап в Яндекс →
`local + backed-up` → «Выгрузить» → `remote` → тап → снова `local`.
Удаление локальной копии разрешено ТОЛЬКО при подтверждённом checksum в облаке.

Файлы: `Documents/Library/<albumId>/<trackId>.<ext>` (ext исходного файла,
без перекодирования; исключены из iCloud-бэкапа). Каталог и обложки —
`Application Support` (бэкапятся). `UIFileSharingEnabled` — Files app как
запасной канал импорта с первого дня.

Все переходы состояний — идемпотентные транзакции; повтор после сбоя
продолжает, а не ломает. Checksum сверяется после каждой передачи.

## Синк Mac → iPhone (pull)

1. Mac: drag-drop папки → парсинг тегов → превью → правка метадаты →
   «Отправить» → альбом в исходящей очереди.
2. Mac публикует `_zver._tcp` (Bonjour) + HTTP-сервер раздачи.
3. iPhone (`NWBrowser` слушает постоянно): нашёл → JSON-манифест очереди →
   дельта против каталога → качает `URLSession.downloadTask`.
4. Файл: скачали → SHA-256 → в библиотеку → каталог → UI.
5. Mac получает подтверждение → убирает из очереди.

Pairing: 6-значный код на Маке при первом подключении → обмен ключами →
дальше доверие по сохранённому ключу.

Манифест и протокол версионируются (JSON-схема) — источником может стать
веб-клиент или бэкенд без изменений на телефоне.

## Плеер

AVAudioEngine + AVAudioPlayerNode (или SFBAudioEngine для DSD).

Sample rate matching перед каждым треком:
1. формат файла → 2. `setPreferredSampleRate` → 3. readback-проверка →
4. пересбор графа на частоте файла → играем. Громкость 100%, ноль DSP.

Gapless внутри одной частоты через предварительный `scheduleFile`.
Обработка: `routeChangeNotification` (выдернули ЦАП → пауза, пересбор),
`interruptionNotification` (звонки).

Системная интеграция: background audio, MPNowPlayingInfoCenter,
MPRemoteCommandCenter (локскрин, Control Center, Watch, наушники).

UI по образцу Apple Music: табы Библиотека/Поиск; экран альбома → трек →
полноэкранный плеер → свайп → мини-плеер полоской над таб-баром.

## Пульт с Мака

iPhone — WebSocket-сервер (тот же `_zver._tcp`), Mac — клиент.
Протокол: команды (`play`, `pause`, `seek:<s>`, `playAlbum:<id>`, …) и
состояние (трек, позиция, очередь — пуш при изменении).

Два режима паузы (настройка):
- **«Пульт всегда на связи»**: на паузе играем тишину (нулевые сэмплы —
  колонки не двигаются, износа нет; ЦАП остаётся захваченным) —
  команды с Мака доходят всегда.
- **«Экономный»**: на паузе приложение засыпает; включить можно с локскрина
  телефона (системная кнопка будит приложение, пульт оживает).

Деградация: телефон не в сети → Mac показывает «iPhone не в сети»,
заливка и редактор работают независимо.

## Яндекс.Диск

`ZverStorage`: протокол `RemoteStore` (upload/download/list/delete/exists),
реализация `YandexDiskStore` (REST, свой клиент на URLSession).

Структура на Диске:
```
Диск:/Приложения/Zver/
  catalog.sqlite.backup
  library/<albumId>/<trackId>.<ext>
```

Очередь бэкапа: новый альбом → background URLSession, 2 параллельных файла,
двухэтапная схема (href → PUT), докачка Content-Range, backoff на 429.
Восстановление: логин → скачать каталог → вся библиотека в ☁️ → качать нужное.

## Порядок сборки (каждый этап — работающий продукт)

1. **Ядро плеера** — iOS: играет FLAC из папки (импорт через Files app),
   ЦАП sample-rate-matching, локскрин, мини-плеер.
2. **Каталог и библиотека** — GRDB, экраны альбомов/артистов, gapless,
   плейлисты.
3. **Синк с Мака** — Mac-приложение: drag-drop, парсинг, редактор метадаты,
   Bonjour + pull.
4. **Яндекс** — бэкап-очередь, выгрузка/докачка, восстановление.
5. **Пульт** — WebSocket, окно на Маке, два режима паузы.

## Тестирование

- Пакеты — юнит-тесты: парсер тегов на эталонных файлах, протокол на
  JSON-фикстурах, каталог на in-memory SQLite, state machine переходов
  fileState.
- Аудиотракт/ЦАП — ручная проверка на железе (индикатор частоты на ЦАПе).
- Синк — девайс + Мак в одной сети.

## Отложено (не в MVP)

- Веб-заливка с телефона (FlyingFox + браузер) — для Windows/чужих компов.
- Собственный бэкенд (протоколы готовы к подключению).
- Fade/кроссфейд, авто-выгрузка давно не слушанного, многопользовательность.
