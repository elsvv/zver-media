# Таб «Главная»: умная лента и AI-рекомендации

Этап 2 из 3 (после «Фундамента» PR #13). Источники сигналов уже есть:
история (`playEvent` + `listeningStats`), избранное, `addedAt`.

## Идея

Первый таб приложения — лента в духе Apple Music Home: карусели-плитки,
часть — локальные (без сети/AI), часть — сгенерированные LLM по статистике
прослушивания. Приложение не стриминг, поэтому дискавери двухслойный:
подборки ИЗ библиотеки + предложка «что скачать» (внешние альбомы с
обложками из iTunes Search API и объяснением, почему зайдёт).

## Слои

### Пакет `Packages/ZverBrain` (чистая логика, TDD)

- `BrainConfig`: `baseURL` (OpenAI-совместимый, напр. `https://openrouter.ai/api/v1`),
  `model`; ключ — через протокол `TokenProviding` (как ZverStorage, Keychain
  в аппе). Никаких провайдер-специфичных SDK: один POST `chat/completions`.
- `ChatClient` (протокол) + `OpenAICompatibleClient` (URLSession): messages →
  text. Таймаут ~120с, ошибки типизированы (`unauthorized`/`rateLimited`/
  `badResponse`), без ретраев (ручной запуск).
- `LibrarySnapshot`: компактная выжимка для промпта — альбомы с короткими
  id (`A1`, `A2`, …; маппинг id→albumKey живёт у вызывающего), топ-артисты
  и топ-альбомы по прослушиваниям, избранное, недавно добавленное/прослушанное,
  жанро-подсказок нет (тегов в файлах не читаем) — креатив на LLM.
- `HomeFeedPrompt.build(snapshot:)`: system + user. System — русскоязычный
  музыкальный куратор: 5–8 секций, категории придумывает сам (настроение,
  декада, «глубокие врезки», связи между артистами…), для library-секций —
  ТОЛЬКО id из списка, 1–2 секции внешних рекомендаций (реальные релизы,
  без изданий из библиотеки), у каждой секции `title`/`subtitle`, у внешних
  элементов `reason` (1–2 предложения, познавательно). Ответ — строго JSON.
- `HomeFeed`/`HomeSection` (Codable):
  `section = {title, subtitle?, tags?, kind: albums|external, albumIds? | items?}`;
  внешний `item = {artist, album, year?, reason}`. Секций-плейлистов из
  отдельных ТРЕКОВ в v1 нет: снапшот отдаёт только альбомы (id треков модели
  неоткуда взять без галлюцинаций) — отложено.
- `HomeFeedParser.parse(text:validIds:)`: вытаскивает первый JSON-блок из
  ответа (модели любят обёртки ```json), декодит, отбрасывает
  галлюцинированные id, пустые секции схлопывает. Ошибка → типизированная.

### iOS

- **`BrainAccount`** (по образцу CloudAccount): ключ в Keychain
  (`KeychainKeyStore`, отдельный account), `baseURL`/`model` в `@AppStorage`.
  Секция «Интеллект» в Настройках: base URL, модель, ключ, статус.
- **`HomeFeedService`** (`@MainActor ObservableObject`): собирает
  `LibrarySnapshot` (LibraryStore + PlayHistoryStore.listeningStats(90 дней) +
  избранное + recentAlbumKeys), зовёт ZverBrain, валидирует, кэширует JSON в
  Application Support (`homefeed.json` + дата), публикует `feed`/`state`
  (idle/loading/error). Обновление ТОЛЬКО вручную.
- **`HomeView`** — первый таб «Главная»:
  - локальная секция «Недавно прослушанное» (recentAlbumKeys → AlbumGroup) —
    работает без AI/сети;
  - AI-секции `albums`: ведущая карточка-обложка на шейдере (заголовок
    секции на «дышащем» градиенте, как плитки Apple Music) + карусель
    альбомов; тап по карточке — экран секции (все её альбомы гридом);
  - `external` → карусель карточек «Скачать бы»: обложка из iTunes Search
    API (фоллбэк — шейдерная), тап — шит с reason и метадатой;
  - тулбар «⋯»: «Обновить рекомендации» (конфирм → запрос), «Интеллект…»
    (в настройки); пустое состояние ведёт туда же;
  - подпись даты последнего обновления.
- **Шейдерные обложки** (`AIPlaylistCover`): SwiftUI `colorEffect` + Metal
  (iOS 17), детерминированный seed от названия секции — медленно «дышащий»
  абстрактный градиент; палитра от hash названия. Анимация только на
  видимых плитках (TimelineView), эстетика > эффектности.
- **`ITunesArtworkFetcher`**: `itunes.apple.com/search?media=music&entity=album`,
  term = «artist album», берём `artworkUrl100`→600×600, дисковый кэш
  (Caches/HomeArtwork). Без ключей; ошибки тихие (фоллбэк-шейдер).

## Решения/границы

- Провайдеры: любой OpenAI-совместимый endpoint (OpenRouter/OpenAI/Gemini
  openai-совместимый URL). JSON-режим не требуем (не везде есть) — parser
  устойчив к обёрткам.
- Промпт-бюджет: снапшот ≤ ~300 альбомов строками `A17: Артист — Название
  (год)`; поверх — агрегаты. Больше — обрезаем с приоритетом
  избранное/прослушиваемое/недавнее.
- Теги: в этом этапе — лайт: секции ленты могут нести `tags` (чипы в UI,
  чисто визуально). Полноценная система тегов с БД и экранами — отдельный
  этап после Mac.
- История «Недавно прослушанное» = recentAlbumKeys (различные альбомы по
  последнему событию), к ленте AI не привязана.
- Ключ не задан → таб живёт с локальными секциями + пустым состоянием AI.
