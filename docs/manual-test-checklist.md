## Этап 3 — синк Mac ↔ iPhone

Подготовка: Мак и iPhone в одной Wi-Fi-сети, на Маке запущен `ZverMac` (иконка в меню-баре).

### На Маке (ZverMac)
- [ ] Drag-drop: перетащить папку альбома (напр. `Radiohead - In Rainbows (2007) [24-44.1 WEB FLAC]`) в окно → распарсились теги, показалось превью с обложкой и списком треков
- [ ] Редактор метадаты: изменить название альбома / артиста / обложку → правка видна в превью, **исходные аудиофайлы на диске не изменились** (проверить дату модификации/теги файла в папке — не тронуты)
- [ ] «В очередь»: альбом попал в исходящую очередь, виден статус раздачи

### На телефоне (ZverIOS, экран «Импорт с Мака»)
- [ ] Обнаружение: Мак появляется в списке найденных (по имени Мака)
- [ ] Pairing (первый раз): Мак показывает 6-значный код, ввод кода на телефоне → успех, токен сохранён; повторный заход на тот же Мак pairing не запрашивает
- [ ] Загрузка очереди: старт импорта → идёт прогресс по файлам/альбому
- [ ] Обрыв сети на середине: выключить Wi-Fi/унести телефон и вернуть → докачка продолжается с места (не качает заново уже скачанное)
- [ ] Целостность: SHA-сверка отбраковывает битый файл — повреждённый трек перекачивается, в библиотеку попадает корректный

### Результат на телефоне
- [ ] Правки с Мака видны в каталоге телефона: изменённые на Маке название/обложка/артист отображаются в библиотеке (sidecar `album.zvermeta.json` лёг рядом с треками, overlay применился)
- [ ] Перезаливка того же альбома: повторно залить альбом с Мака → обновился на месте, **без дублей** в библиотеке
- [ ] Подтверждение Маку: после успешного импорта альбом **ушёл из очереди** на Маке (получен confirm)

## Этап 4 — Яндекс.Диск

Проверка облака — на устройстве у владельца (сети/реального Яндекс.Диска в CI нет;
пакеты и компиляция таргетов зелёные автоматически). Подготовка: владелец получил
~годовой OAuth-токен Яндекс.Диска (scope `cloud_api:disk.app_folder`).

### Авторизация
- [ ] Настройки → вставить токен → «Войти»: статус сменился на «Авторизован», токен лёг в Keychain (после рестарта приложения вход сохранён, повторно вставлять не нужно)
- [ ] «Выйти»: статус сбросился, токен удалён из Keychain
- [ ] Битый/пустой токен: «Войти» не авторизует (нет ложного «Авторизован»)

### Автобэкап
- [ ] Новый альбом (импортирован с Мака или закинут в Documents) автоматически выгружается в облако → на треках появляется бейдж ☁︎✓ (`backedUp`)
- [ ] Бэкап каталога: после батча в облаке лежит `catalog.sqlite.backup` (виден в Яндекс.Диске → Приложения → Zver)
- [ ] Облачная раскладка верна: файлы в `library/<albumId>/<fileName>`, имена зеркалят локальные

### Выгрузка (offload) и удаление только по checksum
- [ ] Swipe по `backedUp`-треку → «Выгрузить»: локальный файл удалён, бейдж стал ☁︎ (`remote`)
- [ ] Удаление локального файла НЕ происходит без подтверждённого checksum: если облачный SHA-256 не совпал с локальным — файл остаётся на устройстве, трек НЕ переходит в `remote`
- [ ] После выгрузки место на устройстве освободилось (файл физически удалён из `Documents/Library/...`)

### Скачивание и воспроизведение
- [ ] Swipe по `remote`-треку → «Скачать»: файл вернулся на устройство, бейдж стал ☁︎✓ (`backedUp`), трек играет
- [ ] Тап по `remote`-треку (файла на устройстве нет) НЕ роняет приложение и НЕ пытается играть пустоту — ведёт на «Скачать»
- [ ] Скачанный трек проходит SHA-сверку и раскладывается атомарно (битый перекачивается, в библиотеку попадает корректный)

### Устойчивость передачи
- [ ] Обрыв сети на середине аплоада: выключить Wi-Fi и вернуть → выгрузка продолжается/повторяется, в итоге трек `backedUp` (аплоад — best-effort: при обрыве перезапрос href и повтор PUT)
- [ ] Обрыв сети на середине скачивания → докачка продолжается с места (не качает заново уже скачанное)
- [ ] 429 (Too Many Requests) от Яндекса НЕ валит очередь: передача уходит в backoff (уважает `Retry-After`) и затем завершается; остальные элементы очереди не теряются
- [ ] Свернуть приложение во время передачи → фоновая сессия продолжает (или корректно докачивает после возврата)

### Восстановление после переустановки
- [ ] Удалить и переустановить приложение (или новое устройство) → войти токеном → Настройки → «Восстановить из облака»: скачивается `catalog.sqlite.backup`, вся библиотека показывается как ☁︎ `remote`
- [ ] Качнуть нужный трек из восстановленной библиотеки → он скачивается и играет

### Mac-guard (миграция каталога v2 не сломала Мак)
- [ ] `ZverMac` по-прежнему запускается (иконка в меню-баре), парсит дропнутую папку и раздаёт очередь по HTTP — миграция каталога v2 (этап 4, iOS-only) не задела Mac-компаньон
