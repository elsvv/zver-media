# Zver Media

Личная медиасистема: синхронизация и воспроизведение lossless/hi-res музыки.
Нативный iOS-плеер с выводом на USB ЦАП + Mac-компаньон (заливка альбомов,
метадата, пульт) + Яндекс.Диск как холодный ярус хранения.

Готовы **этап 1 «Ядро плеера»**, **этап 2 «Каталог и библиотека»**,
**этап 3 «Синк с Мака»** и **этап 4 «Яндекс.Диск»**. Следующий — этап 5 «Пульт».

## Что умеет

- Воспроизведение FLAC/ALAC (включая hi-res) из Documents, переключение
  sample rate USB ЦАПа под частоту трека, управление с локскрина, фон.
- **Gapless**: следующий трек той же частоты предпланируется в аудио-ноду —
  стык треков альбома без паузы и щелчка.
- **Персистентный каталог** (GRDB, Application Support): библиотека
  открывается мгновенно после рестарта, рескан Documents идёт фоном
  и сверяет изменения (upsert + удаление пропавших файлов).
- **Экраны библиотеки**: Плейлисты / Артисты / Альбомы / Песни,
  детали альбома с кнопками Играть/Перемешать, бейджи формата,
  мини-плеер поверх всех экранов.
- **Поиск** (отдельная вкладка): по названию, артисту и альбому,
  результаты секциями; тап по треку играет очередь из результатов.
- **Плейлисты**: создание/переименование/удаление, добавление через
  контекст-меню трека, reorder и удаление в EditMode; хранятся
  в каталоге и переживают рестарт приложения.
- **Фоллбэки импорта**: если у трека нет встроенной обложки — берётся
  `cover/folder/front/albumart.{jpg,jpeg,png}` из его папки; если нет
  тега ALBUM — альбомом становится имя родительской папки.

## Синк с Мака (этап 3)

Pull-передача альбомов **Mac → iPhone** по локальной сети, без облака и кабеля.

- **Mac-компаньон `ZverMac`** — приложение в меню-баре: перетащил папку
  альбома в окно → распарсились теги → превью с обложкой и списком треков →
  инлайн-редактор метадаты → «В очередь». Раздаёт очередь по HTTP.
- **Правки метадаты не трогают исходные файлы.** Изменённые на Маке
  название/артист/год/номер трека/обложка уходят только в манифест синка.
  Телефон при импорте материализует их рядом с треками как версионируемый
  **sidecar** `album.zvermeta.json`; `LibraryScanner` накладывает overlay
  поверх тегов файла (правленая обложка из sidecar **побеждает** встроенную).
  `catalog.sqlite` остаётся чисто пересобираемым кэшем — правки переживают
  потерю/реинсталл БД, рескан идемпотентен.
- **Обнаружение по Bonjour** (`_zver._tcp`): телефон видит Маки в сети,
  выбираешь нужный.
- **Pairing 6-значным кодом** (первый раз): Мак показывает код, телефон его
  вводит → получает токен, который дальше носит в `X-Zver-Token`. Повторный
  pairing не нужен.
- **Докачиваемая загрузка**: дельта-планировщик качает только недостающее
  и изменившееся (сверка по SHA-256); HTTP Range/`If-Range`/resume data
  переживают обрыв сети и продолжают с места. Каждый файл после загрузки
  сверяется по SHA-256 из манифеста — битый перекачивается.
- **Перезаливка обновляет на месте**: `albumId` детерминирован
  (`<artist> - <title> (<year>)`), повторный импорт того же альбома не плодит
  дублей. После раскладки телефон шлёт Маку `confirm`, и альбом уходит из
  очереди Мака.

Вся чистая логика синка (версионируемый JSON-манифест, SHA-256, pairing,
дельта-планировщик, разбор HTTP — парсер, диапазоны, роутинг) живёт в пакете
`Packages/ZverTransport` и покрыта юнит-тестами; рантайм-сетевые объекты
(`NWListener`/`NWBrowser`/`NWConnection`) — тонкие адаптеры в приложениях.

## Яндекс.Диск (этап 4)

Облако как **холодный ярус хранения и бэкап** библиотеки на iPhone. Телефон
становится каталогом-источником правды: файлы держатся локально, в облаке —
или в обоих местах по требованию. Только iOS (Mac-таргет этапа 4 не касается,
но продолжает компилироваться поверх миграции каталога v2).

- **Storage за протоколом `RemoteStore`.** Вся облачная логика — в пакете
  `Packages/ZverStorage` (`upload`/`download`/`list`/`delete`/`exists`/
  `ensureFolder`), а конкретный бэкенд за протоколом. Реализация —
  `YandexDiskStore` (тонкий REST-клиент на `URLSession`, ~7 эндпоинтов
  Яндекс.Диска, двухэтапная схема по временным href, докачка скачивания через
  `Range`/`Content-Range`, фоновая сессия). Абстракция допускает план Б
  (Yandex Object Storage / S3) сменой только адаптера.
- **Жизненный цикл `fileState`** трека в каталоге (миграция v2 добавляет
  колонки `fileState`, `cloudSha`):
  `local` (только на устройстве) → `uploading` → `backedUp` (на устройстве И
  подтверждён в облаке) → `remote` (только в облаке, локальная копия удалена);
  `remote` → `downloading` → `backedUp`. Переходы — чистая функция
  `FileState.canTransition(to:)` + идемпотентные апдейтеры в `CatalogStore`.
  Скан Documents **никогда** не меняет `fileState`, а `reconcile` больше не
  удаляет облачные треки: offload-нутый `remote`-трек физически отсутствует на
  диске и обязан пережить рескан (источник правды о наличии — каталог, не ФС).
- **Очередь фонового бэкапа.** `BackupQueue` (актор-планировщик поверх
  `RemoteStore` + `RetryPolicy`) грузит ≤2 файла параллельно, с дедупом по id,
  докачкой и **exponential backoff** (учитывает `Retry-After`): 429 не валит
  очередь, обрыв сети — ретрай/докачка. Новый альбом (после импорта/рескана)
  автобэкапится; после батча выгружается `catalog.sqlite.backup`.
- **Удаление локальной копии — только при подтверждённом checksum.** «Выгрузить»
  (offload) удаляет локальный файл лишь когда облачный SHA-256 совпал с
  локальным (`cloudSha != nil`), после повторной сверки наличия в облаке. После
  каждой передачи (upload/download) — сверка SHA-256 (переиспользуем
  `ZverTransport.Sha256`); скачивание раскладывается атомарно (зеркало
  `DownloadEngine` этапа 3).
- **Вход — ручной отладочный токен (MVP).** Владелец получает ~годовой
  OAuth-токен (scope `cloud_api:disk.app_folder`) и вставляет в Настройках →
  токен ложится в Keychain (переиспользуем `KeychainKeyStore` из
  `ZverTransport` с отдельным account). Storage кредов не хранит — токен
  инъецируется через `TokenProviding`. Чистая логика OAuth (authorize-URL,
  разбор redirect-fragment) уже написана и покрыта TDD; полноценный
  `ASWebAuthenticationSession`-вход — заготовка, **активируем позже** (нужен
  зарегистрированный на oauth.yandex.ru `client_id`).
- **UI и восстановление.** В рядах треков — облачный бейдж по `fileState`
  (☁︎✓ `backedUp`, ☁︎ `remote`, ↑/↓ — активная передача); swipe-действия
  «Выгрузить» (для `backedUp`) и «Скачать» (для `remote`). Тап по `remote`-треку
  (файла нет) ведёт на «Скачать», а не в проигрывание. Восстановление: вход на
  новом/переустановленном устройстве → «Восстановить из облака» скачивает
  `catalog.sqlite.backup` → `importRemoteCatalog` → вся библиотека показывается
  как ☁︎ `remote`, дальше качаешь нужное.

Чистая логика облака (построение запросов и разбор ответов/ошибок Яндекс REST,
классификация ошибок и математика backoff, планировщик очереди и докачки,
OAuth-URL) живёт в `Packages/ZverStorage` и покрыта юнит-тестами; единственный
рантайм-объект `YandexDiskStore` (`URLSession`) — тонкий адаптер, проверяется
компиляцией, сеть проверяет владелец на устройстве.

## Структура

```
Packages/ZverCore/      — SPM: модели, очередь воспроизведения, координатор частоты
Packages/ZverMetadata/  — SPM: парсинг тегов (Vorbis-комменты), сканер папки, sidecar-overlay
Packages/ZverTransport/ — SPM: чистая логика синка (манифест, SHA-256, pairing,
                          Bonjour-реестр, дельта-планировщик, разбор HTTP)
Packages/ZverStorage/   — SPM: чистая логика облака (протокол RemoteStore + модели,
                          Yandex wire — запросы/ответы/ошибки, RetryPolicy + backoff,
                          BackupQueue, OAuth-URL; YandexDiskStore — URLSession-адаптер)
Apps/ZverIOS/           — iOS-приложение (XcodeGen, проект генерируется из project.yml)
Apps/ZverMac/           — Mac-компаньон ZverMac (меню-бар, drag-drop, HTTP-раздача)
docs/plans/             — дизайн и implementation-планы
scripts/                — вспомогательные скрипты
```

## Сборка

`.xcodeproj` обоих таргетов не хранятся в git — генерируются XcodeGen.

**iOS-таргет:**

```bash
cd Apps/ZverIOS && xcodegen generate
xcodebuild -project Apps/ZverIOS/ZverIOS.xcodeproj -scheme ZverIOS \
  -destination "platform=iOS Simulator,name=iPhone 17 Pro" build
```

**Mac-таргет `ZverMac`** (компаньон для заливки альбомов):

```bash
xcodegen generate --spec Apps/ZverMac/project.yml --project Apps/ZverMac
xcodebuild -project Apps/ZverMac/ZverMac.xcodeproj -scheme ZverMac \
  -destination "platform=macOS" build
```

Открыть в Xcode (`open Apps/ZverMac/ZverMac.xcodeproj`) и нажать **Run** —
приложение появляется в меню-баре. Для синка Мак и iPhone должны быть в одной
Wi-Fi-сети; при первом запуске система спросит разрешение на доступ к локальной
сети.

## Установка на iPhone

1. Сгенерировать проект и открыть его в Xcode:

   ```bash
   cd Apps/ZverIOS && xcodegen generate
   open ZverIOS.xcodeproj
   ```

2. В таргете ZverIOS → **Signing & Capabilities** выбрать **Personal Team**
   (достаточно бесплатного Apple ID, добавляется в Xcode → Settings → Accounts).
3. Подключить iPhone, выбрать его как destination и нажать **Run**.
4. На телефоне разрешить запуск: **Settings → General → VPN & Device
   Management** → доверять профилю разработчика.

### Авто-переподпись через AltStore

Профиль бесплатного Apple ID живёт 7 дней. Чтобы не переподписывать вручную,
поставь [AltStore](https://altstore.io): AltServer на Маке продлевает профиль
автоматически, пока iPhone и Мак в одной Wi-Fi сети. Ограничение free Apple ID —
максимум 3 sideload-приложения одновременно.

После установки пройди [чеклист ручной проверки](docs/manual-test-checklist.md).
